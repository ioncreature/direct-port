# Правила исходящих писем DirectPort

Источник истины для писем клиентам и партнёрам (холодные, после звонка, ответы на запрос).
Применяется и к письмам оператора руками, и к тексту, который готовит модель.

Часть правил автоматически проверяет линтер `apps/api/scripts/lint-email.ts`
(см. раздел [Линт перед отправкой](#линт-перед-отправкой)). Остальное — глазами по этому документу.

## Пунктуация (проверяется линтером)

- **Кавычки только двойные ASCII** `"..."`. Никаких "ёлочек" `«»` и "лапок" `„"`.
  Применяется ко всему: названия компаний, коды ТН ВЭД, цитаты. Это явный маркер
  шаблонного Word/AI-текста, который вычитывают и люди, и спам-фильтры.
- **Дефис только обычный** `-`. Никаких em-dash `—` и en-dash `–`. Em-dash - самый
  яркий маркер сгенерированного текста, после которого получатель теряет доверие.
- **Числа** - запятая как десятичный разделитель (русское оформление): `12,5 %`, не `12.5`.

## Тон и длина

- Тон: первое лицо "я", уважительный, по делу. Без "надеюсь, у вас всё хорошо",
  "не отнимет много времени", "извините за беспокойство".
- Без "революционный", "уникальный", "инновационный", "передовой", "best-in-class".
- Subject короткий и по делу. Если получатель просил указать отдел/тему в Subject -
  указываем дословно, как просили.
- Холодное письмо: коротко (10-14 строк), один понятный оффер, мягкий reply-CTA.
- Конкретику (прайс, сроки, развёрнутое описание) даём, когда получатель её ждёт -
  после звонка или в ответ на запрос, а не в первом холодном касании.

## Что не упоминаем без необходимости

- **Минуты как обещание** ("посчитаем за 10 минут") в холодном письме читается как
  маркетинг. Лучше про результат: "пришлю готовый расчёт в тот же день".
- **Технические детали реализации** (Claude, нейросеть, очереди, пайплайн) - клиенту
  важен результат (Excel с кодами ТН ВЭД, пошлинами, НДС и итоговой стоимостью),
  а не как он считается.

## Подпись

Минимальная для холодного письма:

```
Александр Маренин
hello@directport.ru
directport.ru
```

Контакты бота для CTA: https://t.me/direct_port_bot

## Линт перед отправкой

Перед отправкой прогоняй тело письма через линтер - он ловит типографику из раздела
[Пунктуация](#пунктуация-проверяется-линтером):

```bash
# из файла
pnpm lint-email temp/email-body.txt

# из буфера обмена
pbpaste | pnpm lint-email
```

Коды выхода: `0` - чисто, можно отправлять; `3` - есть нарушения, чинить.

Контентные правила (тон, длина, что писать на какой стадии) линтер не проверяет -
это глазами по этому документу. Слова-запреты, специфичные для DirectPort, можно
добавить в `PROJECT_WORD_RULES` в `apps/api/scripts/lint-rules.ts`.
