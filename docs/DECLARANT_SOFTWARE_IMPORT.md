# Импорт товарной части ДТ в декларантское ПО

Результаты исследования (июль 2026) машиночитаемых форматов, которыми DirectPort может
отдавать товарную часть будущей декларации так, чтобы декларант не перебивал её руками.
Источники — официальные сайты вендоров; оговорки о доступности отмечены по месту.

## Что уже реализовано

**Лист для импорта** — `GET /documents/:id/download-import-sheet`
(`ExcelExportService.generateImportSheet`, кнопка «Файл для декларантского ПО» на странице
деталей документа в админке). Плоский xlsx по официальным правилам «Загрузка товаров из
файла» Контур.Декларанта:

- один лист (Контур читает **только первый лист** файла — поэтому отдельный файл, а не
  четвёртый лист основного отчёта);
- без объединённых ячеек и итоговых строк; одна строка = товарная позиция;
- колонка «№ товара» группирует строки в товары ДТ (официальный механизм Контура);
- страна происхождения — цифровым кодом OKSMT (Контур распознаёт «156» → КИТАЙ автоматически);
- маппинг колонок настраивается в UI Контура один раз и запоминается.

Тот же файл пригоден для универсальных Excel-маппилок других систем: СТМ-Конвертер (СТМ)
и «Заполнитель» (Альта-Софт) — обе позволяют пользователю настроить схему переноса из
произвольной таблицы.

Источник правил: https://support.kontur.ru/declarant/41200-zagruzka_tovarov_iz_fajla

## Дальнейшие шаги (по возрастанию сложности)

### 1. INI-файл обмена Альта-ГТД (умеренный риск)

Единственный публично документированный «прямой» формат: текстовый INI в cp1251
(`imp000.ini`), кладётся в папку `\IN\` Альта-ГТД (авто-подхват). Секции
`[GTD\block.Header]` + `[GTD\block.BlockN]` на товар; идентификаторы полей — графы ДТ:
`33_1` (код ТН ВЭД), `31_NAME`/`31` (наименование/гр. 31), `34_1` (код страны),
`35_1`/`38_1` (брутто/нетто), `42_1` (цена), `41_1/41_2` (доп. единица), `45_1` (ТС),
`46_1` (статстоимость), `44` (документы).

Перед реализацией: сверить идентификаторы с `\DATA\gtdwin.dcf` живой установки — документация
датирована 2022 г. (официальная вики Альта-Софт, сейчас доступна из РФ / через веб-архив:
https://web.archive.org/web/20221208200047/https://wiki.alta.ru/index.php/Форматы_ввода_вывода_Альта-ГТД).
Также у Альта-ГТД есть свой XML («Альта-XML», XSD выгружается из самой программы) и
папка автозагрузки для XML/GTD/TXT/DBF/INI.

### 2. API Контур.Декларант (партнёрство)

Официально существует REST API («создавать и копировать декларации, заполнять документы…
всё, что доступно в веб-интерфейсе»), но доступ и документация — только по договору с
Контуром (заявка → демо-пространство → расчёт лицензии).
https://kontur.ru/declarant/spravka/80827-avtomatizaciya_ved_po_vashim_pravilam

### 3. XML ДТ по альбому форматов ФТС (максимальная универсальность, высокая стоимость)

XSD-схемы альбома форматов публичны (https://customs.gov.ru/techdoc/alboms-format-eldoc,
⚠️ доступ только с РФ-IP), единый формат `urn:customs.ru:Information:ExchangeDocuments`
принимают все три системы (и «Загрузка готового файла декларации» Контура). Но: сотни
полей, обязательные графы за пределами товарной части, обновление форматов ~2 раза в год
(например, альбом 5.23.0 + спецификация 3.4.15 с 01.04.2024). Частичный XML только с
товарной частью может не пройти проверку структуры. Делать после подтверждённого спроса.

### СТМ (ВЭД-Декларант)

Своего открытого входного формата нет: импорт из Excel — через платный СТМ-Конвертер
(маппинг настраивается в его UI), XML — форматы ФТС. Клиентам СТМ достаточно нашего
«листа для импорта» + их конвертера.
https://ctm.ru/продукты/программы/вспомогательные/стм-конвертер

## Что сознательно НЕ делаем

- Подачу ДТ (ЭД-2): отдельный контур с ЭП и оператором ЭД / прямым подключением к ЦИТТУ,
  требует статуса участника документооборота; наша роль — подготовка данных до подачи.
